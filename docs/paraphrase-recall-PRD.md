## 1. 背景与问题定义

### 1.1 一句话问题

用户反馈：**"换个说法可能找不到资料。"**

产品语言：**用户换一种说法提问，约每 2.1 次就有 1 次找不到那篇资料；近三分之一直接被告知"库里没有"，而资料明明在。**

失败时用户看到的文案（`hybrid_search()` 空结果分支）：

> 未找到字面匹配：知识库中没有出现查询实词的内容（已避免用语义相近但无关的文档冒充引用来源）

### 1.2 量化数据（实测，非估计）

测量条件：32 道人工撰写中文改写查询 / top_k=5 / **真实** `bge-small-zh-v1.5-int8` ONNX 模型（tier=`local_onnx`，512 维，非哈希桩）/ 语料为 Holdout B 的 8 篇文档（**只复用文档，不复用其冻结的 57 道题**）/ TEMP 隔离库，未触碰真实 Library。

| 指标 | 值 |
|---|---|
| **失败率@5（top-5 拿不到正确文档）** | **46.9%（15/32）** |
| Recall@1 | 46.9% |
| Recall@3 | 46.9% |
| Recall@5 | 53.1% |
| MRR | 0.481 |
| **空结果率（一条引用都不给）** | **31.2%（10/32）** |
| 拒绝原因分布 | `vector-only(no-lexical-overlap)` **597/597 = 100%**（单一来源） |
| 平均字面候选数 / 向量候选数 | 1.69 / 20.0 |
| **零字面重合 10 题子集** | 失败率 **100%**、空结果率 100%、Recall@1 0% |
| 被拒候选最高 sim ≥ SEM_FLOOR(0.6) 的查询 | 9 条（其中 4 条最终仍返回空结果） |

逐题明细见 `eval/reports/paraphrase_probe.md`，本文不重复。

### 1.2.1 对照基线：T0 真实模型（`local_onnx`）—— 本次改造的 before 值

> ⚠ **基线口径更正**：旧 `eval/reports/holdout_b.md`（冻结于 `c5451b8`，2026-09-23）是**过时 + 词法口径**报告，其 Guard 系数字**不作判据**。**特别说明**：该报告的 FA **0% 是旧口径**产物；**新口径下该基线 per_case 重算同样为 FA 0/8**——两个 0% 数值相同、含义不同：旧口径曾把 `answered`（查找型）题当 insufficient 计 FA，新口径不再如此（详见 §7 问题二）。本次改造的 before 值**一律以 T0 真实模型基线为准**。

| 基线 | 关键指标 |
|---|---|
| **Holdout B · `local_onnx`**（57 题 / 8 篇，hard 32%） | Recall@1 **97.5%** · Recall@3/@5 **100%** · MRR **0.988** · Coverage **100%** · Wrong-document **0%** · No-answer FP **0%** · **False Association 旧口径 12.5%（1 例）/ 新口径 0/8（口径已修正，见 §7 问题二）** · Unnecessary Guard **0%**（普通题进 Guard 2.3%）· citation 结构合法率 **100%**（125 条）· source-range overlap（每题）**98.1%**（53 题） |
| **32 题改写探针 · `local_onnx`** | 失败率@5 **46.9%** · 空结果率 **31.2%** · 零字面重合子集失败率 **100%** |

**⇒ 改造目标**：把探针失败率 46.9% 压到 ≤25%；把 Holdout B 的 **False Association 保持为 0%（新口径；旧口径曾记 12.5%（1 例），且不得新增任何 1 例）**，其余安全红线一格不退。

### 1.3 根因（代码级，QA 已独立验证）

`app/core/search.py::_is_grounded()`（1163-1205 行）是 P0-5/P0-6 为"引用可追溯"**刻意**设置的防编造闸门：

| 候选类型 | 放行条件 | 否则 |
|---|---|---|
| `is_lex=True`（词法路 FTS5/LIKE 命中） | 直接视为 grounded（1190-1191 行） | — |
| 纯向量候选（`is_lex=False`） | **rule B**：章节路径/文档标题含 scope 词 **且** `sim ≥ SEM_FLOOR`（1194-1196 行）；**rule C**：文档级 scope 命中 **且** 切片命中 target 词 **且** 语义（1200-1204 行） | 返回 `vector-only(no-lexical-overlap)` 拒绝（1205 行） |

**全部候选被拒 → `hybrid_search()`（约 1458 行）直接返回空结果**，route 追加 `+no-lexical-hit`。

**结构性缺口**：当 query 的实词在语料里一个都锚不上（scope/target 皆为空列表）时，`hit_s` 为空，**相似度再高也没有通道可走**——597 个被拒切片 100% 死于此。这不是"嵌入不够好"，而是"闸门没有为纯语义命中留出口"。

闸门存在的原因（不得遗忘）：docstring 里的 `postgrey_note` 反例——某文档在比较句里顺带提到 PostgreSQL，若允许"含任一 target 词"即 grounded，它会被向量相似度顶进 Top-5，压过真正讲 PostgreSQL 索引的文档。这道闸门是为了守住 Holdout B 的**误归因底线**——历史目标为 0%，**当前真实状态为 False Association 0%（新口径）**；旧口径曾记 **12.5%（1 例）**，系 `answered` 题被误判所致，**非产品回归**（见 §7 问题二，与本次 A+B 无关）。

**⇒ 结论：闸门不能删、不能绕过，只能开一条有约束的语义出口。**

> ⚠ **分类澄清（措辞纠正）**：`relation_guard` 的运行时 `relation_type`（`causal` / `event` / **`responsibility`**，均 Guard in-scope）与 `search` 的 `question_type`（`coverage` / `quantity` / `person` / `datetime` / `model` / `location` / `general`）是**两套彼此独立的分类，不得混用**——例如 `responsibility` 是 Guard 的运行时 relation_type，**不是** search 的 `question_type`。因此：
> - 语义通道的**排除按 search `question_type` 执行**（如 `coverage`），而不是"把 `negative_no_answer` / `attribution` 这类 gold 类别误当成运行时类型挡在通道外"；
> - **归因安全不靠"排除某个 question_type"**，而由**结构性保障**兜底 —— 语义-only 引用**不得作为「关系归因」证据**（Guard 证据集过滤 `match_mode == "semantic-only"`），见 §5 P0-3。

### 1.4 关键洞察（决定投入合理性）

闸门是**当下**的瓶颈；但**闸门一旦打开，嵌入模型立刻变成决定性变量**。实测（闸门前上限，探针只读复算 `_vec_search()` 得到，可复现）：

| 嵌入器 | 金标文档进入向量候选 | 其中 sim ≥ 0.6 | 最高相似度 |
|---|---|---|---|
| `local_onnx`（bge-small-zh-v1.5-int8） | 31/32 | **13/32** | **0.7320** |
| `HashEmbedder`（现有 eval 口径） | 31/32 | **0/32** | 0.2852 |

在现有闸门下换嵌入器无差别（失败率 46.9% vs 46.9%，+0.0pp）：纯向量候选全被拒，向量语义根本没机会进入排序。闸门一开，两组天差地别。

**⇒ 正确顺序：先开通道（本 PRD）→ 再评估模型 → 模型评估时开闸门前后各测一次。本次改造是后续模型升级的前置条件，不是可选项。**

⚠ 另注意：现有 `eval/run_eval.py` 用 `HashEmbedder`（哈希伪向量，无语义），**永远测不出**同义改写问题——本需求的验收必须使用真实模型口径的探针。

### 3.3 已拍板的改造方向（老胡决定，A+B 组合）

| 项 | 内容 |
|---|---|
| **A. 语义专用通道** | 纯向量候选在与查询**零字面重合**、但 `sim` **显著高于词法候选池**时，予以放行 |

**问题二（独立登记，已就地更正）：False Association 指标口径缺陷 —— 已修正，不是产品回归。**

> ⚠ **定性更正**：本条原登记为「`21ab749` relation_guard 回归导致 Holdout B FA 12.5%」，**该定性错误**。经主理人核实 + QA 独立复验（7/7 PASS），真实性质为**度量口径缺陷**：模型行为正确，是"尺子"把正确答案量成了错误。以下为更正后的事实。

| 项 | 内容 |
|---|---|
| 事实（gold 说什么） | `hb_p_data`「谁负责数据平差与报表编制？」的 gold 为：`answer_state="answered"`、`must_contain=["李岚"]`、`relation=null` ⇒ **gold 明说这题就该回答「李岚」**。 |
| 事实（guard 做了什么） | Guard **答出了「李岚」**，即**行为正确**；所谓"回归"并不存在——`relation_guard` 代码无需改动。 |
| 根因（口径） | 旧 `eval/holdout_b_run.py` 的 `relation_metrics` 把 `answer_state=="answered"`（**查找型题**）当 insufficient 处理：只要 Guard=YES 就记 `fp` ⇒ **一次正确答案被记成"错误归因"**，凭空产生 12.5%。 |
| 修正（A′） | **只改 eval，guard 代码零改动**。`answered` 单列：① 答对人名 → `answered_correct`（**不计 FA**）；② **答错人名 → `answered_fp`（仍计 FA，保留"答错责任人"检测力）**；③ 非 YES → `answered_miss`（不计 FA，由 Unnecessary Guard 口径监督）；④ 未知 state → 保守记 `fp`。**FA 分子含 `answered_fp`、分母仍 = 8（4 no + 3 insuff + 1 answered），未缩小分母**。 |
| 修正后实测 | Holdout B：**FA 0/8（0%）**、`abstention` 3/3、positive/negative 100%、**`unnecessary_guard` 0/44（优于基线 2.27%）**。用冻结基线 `c5451b8` 的 per_case 按**新口径重算**（不重跑算法）→ **基线同样为 FA 0/8**，并暴露基线 `answered_miss = 1`：**基线把这题错误阻断了**，这正是旧口径下"误拦 2.27%"的真正来源。 |
| 性质 | **指标口径缺陷，非产品回归**，**与闸门（`_is_grounded()`）及本次 A+B 语义通道均无关**。 |
| ⚠ 必须带上的口径 caveat | ① **`answered` 桶 n=1**，`answered 100%` **不具外推性**——只能作"该题不再被误判"的单点证据，**不得**外推为整体归因能力结论；<br>② **A′ 对产品行为零影响**（纯度量修正；14 条 Guard 题 per_case 逐条相同）；<br>③ 相对基线的 "blocked 1→0 / answered 0/1→1/1" 是「**换模型（e5）+ `21ab749` 证据过滤**」的**合力**，**不宜全记到 A′ 头上**；<br>④ 基线 `c5451b8` 与当前 `multilingual-e5-small/384` **不是同一嵌入器口径**，跨基线绝对数不可直接比较。 |
| 🔒 边界 | **不在本次 A+B 范围**。A+B 的验收只要求"**不新增 FA**"，判据按**新口径**表述为 **FA = 0%**（见 §5.1 P0-3）；**FA 清零不再是"待修目标"，而是修正口径后即已成立的事实**。 |
